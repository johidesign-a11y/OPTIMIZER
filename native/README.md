# Native Windows bridge

`windows.ps1` runs with Windows PowerShell 5.1 and receives a single JSON request through standard input. It writes one UTF-8 JSON response to standard output. The Electron main process supplies the authoritative tweak catalog and an application-specific AppData backup directory. Renderer-supplied scripts, registry paths, cleanup paths, and file inventories are not accepted as operations.

For ZIP distribution, the main process byte-stages its bundled helper into a fresh private AppData directory and verifies the copy's SHA-256 before launch. This does not copy Internet-zone alternate data streams from an extracted ZIP. PowerShell still uses `RemoteSigned`; stronger machine policy is preserved. The temporary helper is removed after the process closes. The copy check verifies integrity against the bundled bytes; release authenticity remains a separate distribution check.

Supported actions are `state`, `scan`, `history`, `apply`, `restore`, `restorePoint`, `analyzeCleanup`, `clean`, `cs2Scan`, `cs2Apply`, and `cs2Restore`. Every mutation requires `payload.approved: true`; applying or restoring system tweaks also requires administrator access. The desktop review dialog must describe the proposed changes before sending approval. All mutations share an exclusive process-level file lock.

Applying tweaks requires a **verified Windows System Restore point**. An app-created point less than 24 hours old can be reused after Windows confirms its sequence, description, and actual creation time. This preserves the earlier baseline and avoids changing Windows' own restore-point frequency policy; every batch still has a separate exact setting backup. If there is no verified recent app point and creating one fails, no setting is changed. A custom Windows image may have disabled or removed System Protection. The optimizer intentionally does not bypass that protection, disable security features, replace driver settings with guessed values, or promise lower network ping or measured input latency.

Before applying any setting, the backend saves every original registry value and type, absent registry keys, and the existing AC/DC power settings. It flushes the backup to disk and updates its journal before and after each operation. A failed apply attempts rollback in reverse order; incomplete rollback remains visible and blocks further applies until recovery. Restore uses the newest active backup first. Introduced registry values are removed; introduced keys are removed only when empty, preserving unrelated entries. Keep the entire AppData backup directory until you no longer need rollback. Restore points provide a separate Windows recovery path; the app's Restore button restores its own exact setting snapshots and does not trigger a full Windows System Restore reboot.

Preflight skips settings that already have the exact requested type and value, and reports unavailable build/application/power settings with reasons. A selection requiring no changes creates neither a restore point nor a setting journal. This is particularly relevant for a custom Windows image that already includes some preferences. Battery/DC settings are left untouched unless a future authoritative catalog entry explicitly targets them.

The scanner uses Windows CIM and driver registry data. Missing measurements remain unknown. In particular, `Win32_VideoController.AdapterRAM` is not presented as exact VRAM because that 32-bit value truncates modern graphics memory. Monitor resolution and refresh readings are the active modes reported by the display driver; inactive displays may not appear.

Cleanup is restricted to regular, unlocked files at least 48 hours old in the current user's AppData Temp and Windows Temp directories. Both creation and modification dates must pass the cutoff. Roots and inventories are recomputed after approval, and reparse points and their descendants are skipped. Each candidate opens with an exclusive native handle, without initially requesting deletion; the final resolved handle path must remain inside the approved root, and the file attributes and dates are rechecked on that handle. Only then is that same file marked for deletion. Recent, locked, linked, and inaccessible files are skipped. Shader caches, downloads, game files, Prefetch, and registry entries are never cleaned. Deleted temporary files cannot be recovered through a setting backup or restore point; the UI must disclose that before approval.

The CS2 profile discovers registered Steam libraries, including `libraryfolders.vdf`, verifies the game executable, and appends a marked block containing only `fps_max 300` and `fps_max_ui 60`. These conservative caps are a baseline to benchmark, not a guaranteed latency improvement; an RTX 3060 may not sustain 300 FPS in every scenario. It preserves the original bytes in AppData, refuses read-only or linked autoexec files, and refuses existing managed blocks or user-defined FPS caps. Apply and restore stage and flush a same-directory temporary file, verify hashes while holding the existing file open against writes, and atomically replace it. An interruption leaves the original or complete replacement recoverable, rather than an incomplete file. Restore stops if another editor changed the file. Reopen CS2 for the autoexec to load. This bridge does not force Steam launch options or change NVIDIA Reflex; use the game's actual supported Reflex setting when available.

## Windows validation

Linux cannot execute these Windows management operations. Before distributing a build, test on a disposable Windows 10/11 VM with System Protection enabled, then on the intended PC after a verified restore point. Cover approval rejection, non-admin rejection, checkpoint failure without writes, actual CIM discovery, multi-tweak apply/restore, absent-value and binary/type restoration, failure rollback, interrupted-journal recovery, and cleanup exclusion of recent/locked/junction files. Test CS2 file backups and edited-file conflict detection using an actual registered Steam installation. Use Microsoft's PowerShell parser to validate syntax without applying settings:

```powershell
$errors = $null
[void][System.Management.Automation.Language.Parser]::ParseFile(
  (Resolve-Path .\native\windows.ps1), [ref]$null, [ref]$errors)
$errors
```
